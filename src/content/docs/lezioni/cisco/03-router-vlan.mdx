Le VLAN sono reti logiche separate: gli host di VLAN diverse **non possono comunicare** a livello 2. Per farli dialogare serve un dispositivo di livello 3, cioè un router, che instrada i pacchetti da una VLAN all'altra. Questa operazione si chiama **inter-VLAN routing**.

Con un solo cavo tra switch e router si usa la tecnica del **router-on-a-stick**: il collegamento è un trunk 802.1Q e il router crea una **subinterface** logica per ogni VLAN. Ogni subinterface fa da **default gateway** per la propria VLAN.

<Aside type="note">
Il nome "on a stick" deriva dal fatto che il traffico di tutte le VLAN passa da **un'unica interfaccia fisica**, che funziona come un "bastone" tra switch e router.
</Aside>

<Callout icon="information" title="Scenario di esempio">

| VLAN | Nome            | Rete            | Gateway (subinterface)     |
|------|-----------------|-----------------|----------------------------|
| 10   | AMMINISTRAZIONE | 192.168.10.0/24 | 192.168.10.1 (`Gi0/0.10`)  |
| 20   | DIDATTICA       | 192.168.20.0/24 | 192.168.20.1 (`Gi0/0.20`)  |
| 30   | LABORATORIO     | 192.168.30.0/24 | 192.168.30.1 (`Gi0/0.30`)  |

Collegamento: porta **Fa0/24** dello switch ↔ interfaccia **Gi0/0** del router.

</Callout>

## Prerequisiti

- Uno switch con le VLAN 10, 20 e 30 già create e le porte di accesso assegnate (vedi le pagine precedenti).
- Un router Cisco (reale o in Packet Tracer) collegato allo switch.
- Gli host configurati con IP della propria VLAN, maschera `255.255.255.0` e default gateway della subinterface corrispondente.

## Procedura

<Steps>

### Configurare la porta dello switch come trunk

La porta dello switch collegata al router deve trasportare tutte le VLAN:

```bash
Switch(config)# interface fastEthernet 0/24
Switch(config-if)# switchport mode trunk
Switch(config-if)# exit
```

<Aside type="tip">
Su alcuni modelli serve prima `switchport trunk encapsulation dot1q`. Se `switchport mode trunk` dà errore, esegui prima questo comando.
</Aside>

### Attivare l'interfaccia fisica del router

L'interfaccia fisica **non ha indirizzo IP**: serve solo ad attivare il collegamento.

```bash
Router> enable
Router# configure terminal
Router(config)# interface gigabitEthernet 0/0
Router(config-if)# no shutdown
Router(config-if)# exit
```

### Creare le subinterface

Per ogni VLAN si crea una subinterface, con encapsulation 802.1Q e l'indirizzo del gateway:

```bash
Router(config)# interface gigabitEthernet 0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
Router(config-subif)# exit

Router(config)# interface gigabitEthernet 0/0.20
Router(config-subif)# encapsulation dot1Q 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0
Router(config-subif)# exit

Router(config)# interface gigabitEthernet 0/0.30
Router(config-subif)# encapsulation dot1Q 30
Router(config-subif)# ip address 192.168.30.1 255.255.255.0
Router(config-subif)# end
```

<Aside type="caution" title="Attenzione">
Il numero dopo `encapsulation dot1Q` deve coincidere con l'**ID della VLAN**. Il numero della subinterface (`.10`, `.20`, `.30`) è solo un'etichetta, ma per convenzione si usa lo stesso valore della VLAN per non fare confusione.
</Aside>

### Verificare la configurazione

```bash
Router# show ip interface brief
```

L'interfaccia fisica e le tre subinterface devono risultare `up`/`up`.

```bash
Router# show ip route
```

Nella tabella devono comparire le tre reti come **connected** (`C`), una per ogni subinterface.

### Testare la comunicazione tra VLAN

Da un host della VLAN 10 esegui un `ping` verso un host della VLAN 20:

```bash
C:\> ping 192.168.20.10
```

Il primo pacchetto può andare perso per la risoluzione ARP. I successivi devono ricevere risposta.

### Salvare la configurazione

```bash
Router# copy running-config startup-config
```

</Steps>

## Alternativa: switch layer 3

Gli switch multilayer, come il Cisco 3560 o 3650, possono fare il routing inter-VLAN senza router esterno, usando le **SVI** (Switch Virtual Interface). Il trunk verso il router non serve.

```bash
Switch(config)# ip routing
Switch(config)# interface vlan 10
Switch(config-if)# ip address 192.168.10.1 255.255.255.0
Switch(config-if)# no shutdown
Switch(config-if)# exit
Switch(config)# interface vlan 20
Switch(config-if)# ip address 192.168.20.1 255.255.255.0
Switch(config-if)# no shutdown
```

| Soluzione            | Vantaggi                          | Svantaggi                                                   |
|----------------------|-----------------------------------|-------------------------------------------------------------|
| Router-on-a-stick    | Economico, semplice da capire     | Un solo link condiviso: può diventare un collo di bottiglia |
| Switch layer 3 (SVI) | Veloce, instradamento in hardware | Costo maggiore, switch meno comuni nei laboratori           |

## Comandi utili

| Comando                    | Funzione                                           |
|----------------------------|----------------------------------------------------|
| `show ip interface brief`  | Stato e indirizzi di interfacce e subinterface     |
| `show ip route`            | Tabella di routing del router                      |
| `show interfaces trunk`    | Porte trunk attive sullo switch                    |
| `show interfaces gi0/0.10` | Dettagli di una subinterface (VLAN, encapsulation) |
| `show vlan brief`          | VLAN e porte assegnate sullo switch                |

## Problemi frequenti

- **Il ping tra VLAN non funziona:** controlla che il gateway configurato sugli host sia quello della loro subinterface.
- **Le subinterface sono `down`:** verifica che l'interfaccia fisica abbia `no shutdown` e che la porta dello switch sia in trunk.
- **Una VLAN non raggiunge il router:** assicurati che la VLAN esista sullo switch e non sia stata esclusa dal trunk.
- **Subinterface senza `encapsulation`:** IOS non accetta l'indirizzo IP finché non è stata configurata l'encapsulation.

## Esercizio

1. Configura un router-on-a-stick per le VLAN 10, 20 e 30 dello scenario.
2. Collega un PC per VLAN e assegna IP e gateway corretti.
3. Verifica con `ping` che i PC di VLAN diverse comunichino tra loro.
4. Elimina la subinterface `Gi0/0.20` con `no interface gigabitEthernet 0/0.20` e osserva cosa succede ai ping verso la VLAN 20.
5. Come esercizio extra, ripeti lo scenario con uno switch layer 3 e le SVI.
